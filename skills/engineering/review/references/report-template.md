# 审查报告模板

本文件统一定义最终报告结构与 finding 格式。Reviewer 返回所分配角度的内容及检查记录；主会话负责交付完整报告。模板中的 R1、R2 仅示范格式，不要求每栏都有 finding。

## 整理规则

- 保留两个审查栏目，按栏内实际影响排序，不合成整体通过结论或跨维度排名。
- 使用报告内唯一的 R1、R2 等 ID。同一机制的已证实反例合为一条并说明范围，机制不同的问题分别保留；不将未经验证的相邻风险写成事实。
- 同一问题跨栏出现时，在依据最直接的栏目完整描述，另一栏引用其 ID 和所属栏目，避免重复描述或修复建议。
- 严重程度只描述后果：**严重**指核心需求或流程失效、安全漏洞、数据丢失或破坏、重要兼容性回归等；**一般**指影响较局部但有实际后果。测试问题按其放过的错误定级，不按维度或数量定级，也不决定用户是否必须修复。

## 完整模板

```markdown
## Review

- Candidate：<SHA / diff hash / PR head>
- 范围：<本轮审查范围；复查时注明前次候选及比较限制>
- 审查记录：<各 reviewer 的记录引用及执行证据的重要缺口>

### 需求符合性

- 检查情况：<已检查范围及依据；重要缺口或待确认点；未检查时说明原因>
- <有跨栏引用或旧问题复查状态时，在此列出 ID、所属栏目或状态及依据>

#### R1 [严重 / 一般] <问题标题>

- 位置：<文件路径与行号>
- 依据：<有效需求、约束、验收标准或行为契约>
- 失败场景：<问题在什么条件下发生>
- 证据：<核验方式、关键事实及反证核验，关联检查记录和代码位置；区分来源、代码推导与已执行检查，注明已证实范围>
- 影响：<对用户、数据或系统的后果>

### 正确性与回归

- 检查情况：<已检查范围及依据；重要缺口或待确认点；未检查时说明原因>
- <有跨栏引用或旧问题复查状态时，在此列出 ID、所属栏目或状态及依据>

#### R2 [严重 / 一般] <问题标题>

- 位置：<文件路径与行号>
- 依据：<有效需求、约束、验收标准或行为契约>
- 失败场景：<问题在什么条件下发生>
- 证据：<核验方式、关键事实及反证核验，关联检查记录和代码位置；区分来源、代码推导与已执行检查，注明已证实范围>
- 影响：<对用户、数据或系统的后果>

### 汇总

- 需求符合性：<本栏独立问题数；未检查时说明原因>；最重要：<ID 与影响，或无已证实问题 / 未检查>。
- 正确性与回归：<本栏独立问题数；未检查时说明原因>；最重要：<ID 与影响，或无已证实问题 / 未检查>。
```

## 状态与计数

- **有 finding**：每条都保留上述五个分项、唯一 ID 和严重程度，不能仅因信息散落在段落中而省略分项。
- **已检查且无 finding**：保留栏目及检查情况，写“未发现有具体证据支持的问题”；不保留空 finding 占位。
- **未检查**：保留栏目并说明原因，汇总写“未检查”而非“0 个问题”；缺少需求依据时明确注明。
- **复查**：沿用旧 ID，列出“已解决 / 仍存在 / 无法核验”及依据；旧 finding 不成立时明确更正，仍成立或新发现的问题保留完整分项。
- **计数**：只统计在本栏完整描述、当前仍成立的独立问题。跨栏引用、已解决项、被撤销项、无法核验项及未决分歧不计入；最重要问题可引用另一栏的 ID，但不增加数量。数量用于概览，不代表质量评分或审查全面性。
